# Irodori Drama Studio

ローカルAIで台本を作成し、複数の話者による音声ドラマやポッドキャストを制作するアプリです。

## 機能

- タイトル、概要、方向性、キーワード、主要セリフ、感情、目標時間の設定
- 話者ごとの参照音声、性格、役割、話し方、一人称、呼ばれ方、相手の呼び方、話すペース、音量、定位の編集
- Ollamaによるあらすじ生成・編集から台本生成へ進む制作フロー
- 目標時間に合わせた場面構成・台本分量の検査と、重複発言の検出・書き直し
- セリフ単位の編集・並べ替え・試聴、複数話者の同時発話
- 音声生成前の台本テキスト出力（保存先を選択）
- Irodori TTSによる音声生成と生成済みセリフの再利用
- 合成伴奏、手持ちのBGM、ルールによるSE配置、会話中のBGM音量低減
- MP3、WAV、声のみ、台本、字幕、設定情報、ZIPの書き出し
- プロジェクト保存、下書き復元、生成の中止

初回起動時は、音声未登録の汎用話者と空の台本を作成します。音声、モデル、生成物は同梱していません。

## 必要な環境

- Python 3.10以上
- Irodori TTS v4.1 Small Quantized（int8）の実行環境と対応モデル
- CUDA対応GPU（音声生成）
- Ollamaと `qwen3:8b` または `qwen3:4b`
- PATHから利用できるffmpeg

Irodori本体とモデルは、それぞれの公式配布元の手順で別途導入してください。このアプリに第三者のモデルや音声素材は含まれません。モデルと素材の利用条件は各配布元をご確認ください。

## セットアップ

1. IrodoriのPython環境で依存パッケージを導入します。

   ```shell
   python -m pip install -r requirements.txt
   ```

2. 次の環境変数を必要に応じて設定します。

   | 変数 | 用途 |
   | --- | --- |
   | `IRODORI_HOME` | Irodoriソースの場所。Pythonからimportできる場合は省略可 |
   | `IRODORI_CHECKPOINT` | 使用する `model.safetensors`。省略時はHugging Faceの標準キャッシュから検索 |
   | `HF_HOME` / `HF_HUB_CACHE` | Hugging Faceの標準キャッシュ設定（任意） |
   | `DRAMA_PYTHON` | Windows起動用スクリプトで使うPython（任意） |
   | `FFMPEG_BINARY` | ffmpegの実行ファイル（任意）。省略時はPATHから検索 |
   | `DRAMA_OLLAMA` | Ollama接続先。既定値は `http://127.0.0.1:11435` |
   | `DRAMA_DATA_DIR` | 実行時データの保存先。既定値はリポジトリ内の `data` |

   `.env.example` は設定項目の参考です。自動では読み込みません。実際の値はシェルで設定し、Gitには保存しないでください。

3. Ollamaを起動し、台本用モデルを取得します。標準ポートでOllamaを利用している場合は、アプリ側の `DRAMA_OLLAMA` をその接続先に変更できます。

   PowerShellで専用ポートを使う例：

   ```powershell
   $env:OLLAMA_HOST = '127.0.0.1:11435'
   ollama serve
   ```

   別のPowerShellで：

   ```powershell
   $env:OLLAMA_HOST = '127.0.0.1:11435'
   ollama pull qwen3:8b
   # Optional, for the faster writing mode:
   ollama pull qwen3:4b
   ```

4. アプリを起動します。

   ```shell
   python server.py
   ```

   ブラウザーで `http://127.0.0.1:8787` を開きます。Windowsでは環境設定後に `start.cmd` も使えます。

## 使い方

1. 企画画面で内容と目標時間を入力します。
2. キャスト画面で話者を追加し、使用可能な参照音声を自分で登録します。
3. あらすじを生成して候補を確認し、「このあらすじを使う」で適用します。直接入力や編集も可能です。
4. 編集したあらすじをもとに台本を生成し、確認して適用します。話者、セリフ、感情、間を編集できます。
5. 声を揃える場合は話者ごとに行を作り、2人目以降の「前の発言と同時」にチェックします。連続する同時発話は同じ開始時刻で重なり、全員が話し終わってから次へ進みます。
6. 台本画面の「台本を保存…」で、保存先を選んでテキストを書き出せます。ChromeまたはEdgeを使用してください。台本にはあらすじ、呼び方、話すペース、同時発話の指示も含まれます。
7. BGMとSEを設定して、音声ドラマを生成します。完成音声を試聴し、必要な形式で保存します。

台本AIと音声生成は、このアプリでは同時に実行しません。台本生成が終わってモデルを解放してから音声を生成します。

## 演出と制限

- 内蔵BGMはアプリ内で合成する簡易伴奏です。本格的な楽曲生成モデルではありません。
- 自動SEはシーンの境界と語句によるルールです。各セリフで種類を変更したり無効にできます。
- 台本、発音、感情表現はAIの出力です。編集と試聴で確認してください。
- 目標尺への調整は、自然さを保つため速度比0.8〜1.25の範囲に限定しています。
- 台本の推定時間は各話者のペース・発言後の間・同時発話を考慮し、指定時間の±10%以内を検査します。実際の読み上げ時間は発音や演技で変わります。
- あらすじを約20秒ごとの異なる展開に分け、各展開は最大4回まで分量と重複を検査して補筆・修正します。展開ごとの長さには幅を持たせ、不足分は後の展開に配分します。全体の条件を満たせない場合は失敗理由を表示し、既存台本を保持します。意味が似た会話を完全に検出できるわけではないため、内容も確認してください。
- 個別の話すペースは全体の話速に乗算されます。同時発話でも各人物の話すペースは維持されます。
- 企画JSONには音声データを含みません。別の環境では音声を再登録してください。
- ローカル利用向けです。ネットワーク公開用の認証やアクセス制御を備えたサービスではありません。

## データとバージョン管理

実行時データは `data/` に保存します。アップロード素材、モデル、キャッシュ、履歴、スクリーンショット、生成物、個別環境設定をGitに追加しないでください。

配布用ファイルを確認するには：

```shell
python scripts/check_distribution.py
```

検査は追跡ファイルの許可リスト、ファイル形式、秘密情報の代表的パターンを確認します。個人情報の不存在を自動判定できるものではないため、コミット内容は目視でも確認してください。

## テスト

```shell
python -m unittest test_core.py -v
```

基本テストはモデル、GPU、音声素材を必要とせず、一時ディレクトリ内の合成信号だけで実行します。実際のAIモデルを使用する生成は各環境で別途確認してください。
